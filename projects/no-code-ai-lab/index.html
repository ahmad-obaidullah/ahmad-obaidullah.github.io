The problem

An e-commerce retailer loses $290,000 a year to returns: a 29% return rate, with Clothing alone generating $132,200 (45.6% of return costs). The goal: flag high-risk orders before fulfillment and eliminate ~22.4% of overall return costs (~$65,000).

Why "no-code" still means rigor

The lab's point is the full lifecycle: define the problem, prepare the dataset, train, evaluate, audit for bias; the same discipline as coded ML, executed on platforms like Google AutoML and Teachable Machine. The engineering judgment lives in the data decisions, not the syntax.

What I did so far: the module timeline

Module 1: Platform reconnaissance

Explored Teachable Machine and Google AutoML; proposed two practical AI use cases (an office email sorter and a recycling sorter) to anchor the lifecycle in real problems.

Module 2: Dataset engineering

Prepared 5,000 orders from the Kaggle synthetic e-commerce returns dataset; dropped 4 identifier columns and 8 post-return leakage fields (Return_Reason, Days_to_Return, Return_Cost, and 5 more); exported automl_ready_returns.csv (11 clean features, zero missing values) and documented the 71/29 class imbalance.

Module 3: Training

Trained a Gradient Boosted Decision Tree classifier with a stratified 80/20 split; found that the default 50% decision threshold missed over 90% of returns, and optimized it to 0.28 to prioritize recall on the minority class.

Module 4: Evaluation & bias audit

ROC-AUC 0.5825, overall recall 60.69%; Clothing recall 92.42% (122/132 returns caught), high-discount orders 75%, low-discount orders 44.34%, Toys 23.53%; a demographic audit found a 15.42% recall gap (female 68.24% vs male 52.82%) traced to catalog composition, not algorithmic bias.

The impact so far
  • Feature importance says pricing drives returns: Discount_Applied 20.88%, Product_Price 15.43%, Clothing 13.46%, Order_Value 12.53%; demographics under 2%.
  • The trade-off is quantified: catching 60.69% of returns costs 338 false alarms per 1,000 orders → next step is category-specific thresholds (0.22 for Clothing vs 0.35 for Electronics/Toys), SMOTE oversampling, and behavioral features.
  • Honest evaluation: a model that looks accurate can still be operationally wrong; class imbalance is where naive accuracy goes to die.
